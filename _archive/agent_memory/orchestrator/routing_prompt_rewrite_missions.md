Lessons from PLAN-2026-W28 (prompt architecture v3, DR-004):

- For any prompt REWRITE mission, the qa gate brief must mandate a rule-by-rule diff of the new prompt against the previous version. **Why:** a silent drop of two safety calibration anchors (BUG-007, critical) survived brainstorm authorship AND two critic review passes; only qa's line-by-line v1-vs-v2 diff caught it. **How to apply:** put "diff every new prompt against its predecessor, list any content absent" as an explicit checklist item in the C2-style gate brief.
- Token budgets set at design time can be infeasible for the densest prompt; adjudicate overshoot via ADR (correctness over budget), never allow silent trimming. **Why:** safety v2 needed 2,545 chars vs the 1,900 design target once all load-bearing rules were kept (ADR-008). **How to apply:** pre-authorize "document the overshoot honestly rather than cut content" in developer briefs.
- Numeric disputes between two specialists are cheapest resolved by the orchestrator grepping the raw artifact directly (one tool call), not by a third dispatch. **Why:** VP-002 run2 CTRS dispute (critic vs tracker) settled in one grep; tracker was right, critic's own cited figure was transposed. **How to apply:** for single-number disagreements with a known artifact path, verify directly; reserve tie-breaker dispatches for interpretive disagreements.
- Every discussion.md Edit after a subagent wave fails with "File has not been read yet" — Read the tail immediately before each Edit. **Why:** background agents invalidate my file-state tracking. **How to apply:** batch status updates; always Read-then-Edit.
- Parallel writes are safe when briefs state per-file territory explicitly (writer on PRD/checklist ∥ developer on prompts/code worked cleanly; both were told the other's files are out of scope).
- Safety-calibration prompt changes on small LLMs over-generalize to adjacent expression classes: elevating passive-SI to CTRS 2 (safety v3, ADR-010) made the model escalate self-harm-ideation-without-SI and burden-feeling lead-ins too — despite explicit carve-out text, and despite passing qa diff + critic pre-run review. Only the live scenario matrix caught it (EXP-003 → rollback per ADR-012). **How to apply:** for any crisis-threshold prompt change, treat the live SM matrix as the real gate, wire adjacent-class scenarios into the rollback trigger set BEFORE running, and budget for at least one failed iteration. Loose OR pass-criteria can mask behavioral divergence (REV-005/VAL-004) — ask what the criteria would NOT catch. (2026-07-07)
- Fix measurement-instrument bugs (f1.py harness class) in ONE batch between validation campaigns, never mid-campaign — instrument parity keeps A/B comparisons meaningful (ADR-009/ADR-012; BUG-011+VAL-001 deferred to a single repair pass before EXP-004). (2026-07-07)
- My own PLAN status-update paraphrases are NOT governing text — REV-008 caught a "무관한 도메인" qualifier I introduced while summarizing the F2 rollback rule that existed nowhere in the governing docs; the categorical rule fired. **How to apply:** when adjudicating a rollback/gate rule, quote the governing document verbatim in the brief, never my summary. (2026-07-08)
- Rollback consequence for a v1 artifact (no predecessor pin): non-certification — keep code as EXPERIMENTAL/UNCERTIFIED, block gate progression, require vN+1 remediation through the full gate chain; commits/PR may proceed if the uncertified status is stated front-and-center (ADR-014, PR #33). (2026-07-08)
- Behavioral rules living only in prompt prose get violated live (4th recurrence per critic's own memory): if a rule can be code-enforced (e.g. evidence-quote risk-lexicon filter in the grounding whitelist), enforce it in code before betting a live batch on it. (2026-07-08)
- Relative-path Glob can spuriously return "No files found" late in a session — retry with an explicit `path` parameter before concluding a file is absent (nearly mislabeled a shipped route as unbuilt). (2026-07-08)
- Never run a citation-heavy doc writer in parallel with a task that MUTATES the files being cited — the dev-environment guide quoted pre-scrub compose/Makefile line numbers and needed a full re-anchoring pass. **How to apply:** sequence doc-writing AFTER repo mutations land, or scope the writer away from files the mutating task touches. (2026-07-08)
