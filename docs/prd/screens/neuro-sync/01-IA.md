### 1.1 네비게이션 구조

| 영역 | 네비 패턴 | 구성 |
|------|----------|------|
| Public | Stack | onboarding → login ↔ register |
| Patient 최상위 | **Bottom Tab Navigator** | Home / Hospitals / Settings (3 tabs) |
| Intake | **Linear Stack (Modal)** | chat → phq9 → gad7 → documents → submit (뒤로/저장 후 종료) |
| Emergency | **Modal Stack** (root) | 위험 감지 시 어떤 화면에서든 모달로 강제 전환 |

**Why Bottom Tab over Top/Side**:
- 한 손 조작 (환자 대부분 우울/불안 상태, 인지부하 최소화)
- 핵심 3개 액션(문진/병원/설정)이 동등한 무게 → Drawer 비추천
- PRD §2.1 "위기 순간 즉각 응급 안내" — Emergency는 탭 외부 모달로 어디서든 노출

## 3. 페이지 그룹 (Grouping & Hierarchy)

### 3.1 Group A: 진입 (Entry)
- `/onboarding`, `/login`, `/register`
- **목표**: 첫 사용자 마찰 최소화 + 4개 동의 분리 수집 (FR-001/FR-026)
- **이탈 지점**: 동의 거부, 비밀번호 정책 미달, 만 14세 미만(Phase 2)

### 3.2 Group B: 사전 문진 (Pre-Intake Pipeline)
- `/intake/chat → /intake/phq9 → /intake/gad7 → /intake/documents → /intake/submit`
- **목표**: 환자 비정형 입력 → 구조화 데이터 (FR-004~010)
- **특수 조건**:
  - 어디서든 위험 발화 감지 시 `/emergency`로 강제 전환 (FR-005, §5.5 Flow C)
  - 백그라운드 자동 저장 — 앱 종료 후 재진입 시 이어하기 (`ns://intake/resume`)
  - Demo: `/intake/documents`는 Stub (Skip 가능)

### 3.3 Group C: 결과 (Outcome)
- `/report/status` (환자 입장에서 리포트는 "전달 준비 완료"까지만 확인. 실제 Handoff Report 본문은 의료진 웹 전용)
- **목표**: 제출 후 환자 불안 해소 — "내 정보가 의료진에게 잘 전달되고 있다"는 신호

### 3.4 Group D: 안전망 (Safety Net)
- `/emergency` (Modal Stack, 어디서든 트리거)
- **목표**: 위험 상황 즉시 응급 핫라인 노출 (PRD Appendix D)
- **트리거 경로 3종**:
  1. AI 채팅 중 Safety Guard 감지 (자동) — FR-005
  2. 환자가 홈/설정의 "지금 도움이 필요해요" 버튼 클릭 (수동)
  3. (Phase 3) 외부 딥링크

### 3.5 Group E: 부가 기능 (Auxiliary)
- `/hospitals` (Phase 2), `/settings`
- **목표**: 진료 전후 부가 가치 (병원 찾기) + 자기결정권(동의 변경/탈퇴)

## 5. 컨텐츠 우선순위 (Content Hierarchy per Screen)

각 화면의 첫 화면 진입 시 환자가 **3초 안에 인지해야 하는 1순위 요소**.

| Route | 1순위 (Above the Fold) | 2순위 | 3순위 |
|-------|----------------------|------|------|
| `/onboarding` | 핵심 가치 1줄 + "다음" 버튼 | 진행 인디케이터 (1/4) | 건너뛰기 |
| `/login` | 이메일/비밀번호 입력 + 로그인 버튼 | 회원가입 링크 | 비밀번호 찾기 |
| `/register` | 현재 스텝 제목 + 진행률 | 입력 필드 | 다음 버튼 |
| `/home` | "사전 문진 시작하기" 1차 CTA | 진행 중 세션 카드 (있으면) | "지금 도움이 필요해요" 응급 진입 |
| `/intake/chat` | AI 인사말 + 입력창 + 마이크 | 진행률 헤더 | "그만하기" |
| `/intake/phq9` | 현재 문항 (3~9) + 5점 척도 | 진행률 (n/9) | 이전/다음 |
| `/intake/gad7` | 현재 문항 + 5점 척도 | 진행률 (n/7) | 이전/다음 |
| `/intake/documents` | "추가하기" CTA (Demo는 "Phase 2에 제공" 안내) | 업로드된 문서 목록 | "건너뛰기" |
| `/intake/submit` | 입력 요약 + "최종 제출" | 안내 문구 (Appendix C) | 이전으로 |
| `/emergency` | **1393 전화 걸기 큰 버튼** | 119, 1577-0199 | "지금 혼자 있나요?" 안전 질문 |
| `/hospitals` | 지도 또는 위치 권한 요청 | 가까운 병원 리스트 | 응급 필터 |
| `/report/status` | 상태 배지 (생성중/완료) + 메시지 | 예상 소요 시간 | 홈으로 |
| `/settings` | 프로필 카드 (이름/연락처) | 동의 관리 진입 | 로그아웃 |

## 6. RBAC 매트릭스 (모바일 한정)

| Role | 모바일 접근 가능 페이지 | 모바일 차단 |
|------|---------------------|-----------|
| `guest` | `/onboarding`, `/login`, `/register` | 그 외 모두 → `/login` 리다이렉트 |
| `patient` | 모바일 전 페이지 | 의료진 페이지 (모바일에 없음) |
| `clinician` | (모바일 미지원) | 로그인 시 "본 앱은 환자용입니다. 의료진은 웹 대시보드를 이용하세요" 안내 + 로그아웃 |
| `org_admin` / `super_admin` | (모바일 미지원) | 동일 안내 |

**구현 노트**: `/api/v1/auth/login` Request에 `role: 'patient'` 고정. 의료진 계정으로 로그인 시도 시 백엔드가 403 ROLE_MISMATCH 반환 → 클라이언트가 안내 모달 표시.

## 7. 화면 간 데이터 의존성

```
/register (consents JSON) ──> /home (read userId)
                                 │
                                 ├─> /intake/chat (sessionId 생성)
                                 │       │
                                 │       └─> messages[], risk_events (생성)
                                 │
                                 ├─> /intake/phq9 (sessionId 참조) → questionnaire_results
                                 ├─> /intake/gad7 (sessionId 참조) → questionnaire_results
                                 ├─> /intake/documents (sessionId 참조) → documents (Phase 2)
                                 │
                                 └─> /intake/submit (sessionId 참조) → reportId 생성
                                         │
                                         └─> /report/status (reportId polling)

/settings ──> consent_snapshots (FR-026/034 변경) ──> WebSocket 재인증
```

**Critical Path (데모 시연 핵심)**:
`/login → /home → /intake/chat → (위험 시) /emergency → /home`
`/login → /home → /intake/chat → /intake/phq9 → /intake/gad7 → /intake/submit → /report/status`
