## Part A — golden domain labels (VP-001 through VP-012)

### Domain enum and mapping principle

8-value enum (source: `docs/ai/PRD_task1.md:474`): `anxiety | depression | alcohol | substance | trauma | sleep | psychosis | other`.

**Base rule (all 7 VPs).** A domain is included in a VP's golden set only if the persona's own **chief complaint (주호소) or stated diagnosis** names it — not merely because a secondary scale score (PHQ-9/GAD-7) crosses a severity-band label, and not because a risk-assessment or coping-behavior field mentions it. Applied uniformly so no VP gets an ad hoc inclusion/exclusion decision; every exclusion below is flagged explicitly, not silently decided.

**Extension for VP-010/011/012 (disclosed interpretive extension, `DATASET-003-ext`).** VP-010's minimization tiers and VP-011's somatic masking mean the SURFACE-level (Tier-1) chief complaint text is, by design, clinically uninformative or actively misleading (VP-010 Tier-1: "그냥 요즘 좀 피곤하고 스트레스 받아서 왔어요"; VP-011's surface 주호소: "두통, 소화불량, 만성피로" — zero psychiatric-domain words). Applying the base rule to the SURFACE layer for these two would license nothing for either persona. The license source for VP-010/011/012 is instead the **ground-truth** clinical-profile/expected-scale-score/expected-slot-value content (the persona's authored TRUE clinical picture, not the minimized/masked surface dialogue) — each file's own label-grounding note explicitly designs for this reading. The underlying chief-complaint-or-diagnosis discipline still governs which ground-truth content counts; only the *layer* read (ground truth vs. surface) differs for these three.

**VP-002 = `{depression}`.** Single domain: chief complaint is an explicit revisit for a diagnosed "경도 우울 에피소드" on Escitalopram, improving. **Excluded: anxiety.** GAD-7 ~5 "Mild anxiety" is present in the scale table but no diagnosis, chief complaint, or clinical-judgment line anywhere in the file names anxiety as a domain.

**VP-003 = `{depression}`.** Chief complaint: "극심한 우울, 자살 사고, 절망감." The suicidal-ideation content in this same phrase and the persona's 위험 평가 section ("자살 사고: 수동적 자살 사고 (매일)", §2) are **risk signal, not a domain value** — the 8-value enum has no suicide/risk member. **VP-004 = `{depression, anxiety}`.** Chief complaint documents two co-occurring domains: an existing depressive episode ("이전 진단: 주요우울장애 의심"; "중등도 우울로 치료 시작") and newly-onset panic attacks with an ER visit one month prior ("공황 발작이 새로 발생하여 1개월 전 응급실 방문"). **Deviation, reasoned:** the domain enum has no `panic` value, so panic → `anxiety` — DSM-5 classifies Panic Disorder under Anxiety Disorders, and the persona's own `anticipatory_anxiety` expected slot ("또 그러면 어떡하지 하는 생각이 자꾸 들어요") is a core panic/anxiety-spectrum symptom by name, independently corroborating the mapping. ### Scoring rule (pre-registered before any live run, unchanged across VP-001~004 and VP-010~012)

- **Top-1 hit:** the model's rank-1 domain (`domain_candidates[0].domain`) ∈ the VP's golden set. Binary.
- **Top-3 hit:** ANY element of the VP's golden set appears anywhere among the model's returned `domain_candidates` (capped at ≤3). Binary, existential match (OR across golden-set elements).
- **No partial credit.** A 2-element golden set (VP-001, VP-004, VP-010, VP-012) scores the same top-1/top-3 hit as a 1-element set (VP-002, VP-003, VP-011) if any one element matches — no fractional credit, no penalty for surfacing only one of two valid domains.
- **0-candidate case (amendment, `REV-007`):** `domain_candidates=[]` scores as a miss (0) for both top-1 and top-3 for that VP/run — the agent's own designed degrade behavior (no silent fabrication) produces this as a live, expected outcome, not a hypothetical edge case.
- **Reporting format:** raw counts only, no percentage/rate claims (e.g. "top-1 X/N") until ≥12 cumulative observations exist.
- **Department scoring:** descriptive only, not scored, for all 7 personas. All are framed throughout as psychiatric pre-consultation intake (VP-001/003/010/011/012: first-visit, no prior prescriber; VP-002/004: explicit prior "정신건강의학과" prescriber).
- **Golden-set-cardinality asymmetry caveat (new finding, `REV-026`, binding wording discipline).** A 2-element golden set (VP-001, VP-004, VP-010, VP-012) has a structurally higher a-priori top-1/top-3 hit probability than a 1-element set (VP-002, VP-003, VP-011), independent of system quality, under the existential-OR scoring rule above. This is not a defect in the labeling — every comorbid call above is independently well-grounded in ground-truth text, and the direction is not self-serving (e.g. VP-011's single-domain call makes scoring *harder*, not easier). **Any W8 report comparing raw hit rates across 2-element-golden-set VPs vs. 1-element-golden-set VPs without disclosing this cardinality asymmetry risks an apples-to-oranges read.**

### Golden-label discipline — circularity caveat (binding on all 7 cards)

Restated verbatim, binding on any correctness claim drawn from any label in this file: "structural circularity between the golden label and F2's own input features... single-pass authorship; independent-source authorship is not available for this batch either." In full: the golden domain label and F2's eventual input text (F1's `final_slots`, produced by an interactive session between the real `DialogueAgent` and an LLM patient-simulator whose system prompt is drawn directly from the SAME persona file's clinical-profile content these labels are also derived from) are **not independently sourced** — both trace back to one paragraph in one file, authored in one pass, with no held-out or blinded generation step between them. **High fabrication-0/top-1/top-3 accuracy against any VP's golden label in this file cannot be read as evidence the pipeline generalizes beyond this closed, self-consistent persona set.** This caveat is binding on all 7 VPs alike (VP-001~004 per `DATASET-004`; VP-010~012 per `DATASET-003-ext`, re-incurred, not resolved by being a newer persona set).

## Part B — golden reveal-partition spec (SC-4/SC-5/SC-8 chains)

Which persona facts are gated to session 2+ for the live multi-session `continuous_test.py` chains, authored blind, before any multi-session run.

### Chain-eligibility finding (binding on this spec's design)

Not all 4 of VP-001..004 are structurally suitable for `continuous_test.py`'s live `--persona VP-00X --sessions N` chaining mechanism, which reuses ONE persona's ONE static system prompt across every session in the chain. `f1.py:2197-2198` — the SYSTEM always treats `session_index=1` (no `--followup-from`) as `is_revisit=False`, regardless of the persona file's own `visit_type` metadata (independently confirmed structural, not a narrow edge case, by tracing `continuous_test.py:399-408`: `followup_from` is unset for every session-index=1 in any chain attempt). But VP-002's and VP-004's static Patient LLM simulation prompts hardcode revisit framing **unconditionally**: VP-002 — "오늘은 약 복용 후 경과를 확인받기 위한 재진 사전문진입니다" (`VP-002_revisit_mild.md:322`); VP-004 — "오늘은 재진 사전문진입니다" (`VP-004_revisit_severe.md:385`). Chaining VP-002 or VP-004 fresh (session 1, no `--followup-from`) would therefore produce an internally contradictory session: the SYSTEM's own greeting/dialogue framing treats it as first-visit, while the PATIENT simulator insists this is already a revisit. VP-001 and VP-003, by contrast, both state unconditional first-visit framing ("정신과를 방문한 적은 없습니다") with no revisit claim anywhere in their static prompts, and chain cleanly.

**This spec designates VP-001 and VP-003 as the SC-4/5/8 chain-relevant personas; VP-002/VP-004 are excluded from live `continuous_test.py` chaining by this structural finding** (RATIFIED, `REV-026` ruling 2 — independently re-verified against the same cited lines, confirming the conflict is structural for every possible VP-002/VP-004 chain attempt, not a narrow edge case).

**Persona-diversity scope-limit wording discipline (binding, `REV-026` ruling 2).** Any W7b/W8 report characterizing SC-4/SC-5/SC-8 multi-session results as validating induction/re-probe/revision behavior "across the persona set" overclaims — the multi-session battery exercises only VP-001 (mild, first-visit) and VP-003 (severe, first-visit), two of seven personas, both first-visit. **State this explicitly wherever SC-4/5/8 results are reported.**

### Reveal-partition design, per SC class

All three targets are drawn from the 8 canonical `QUESTIONABLE_SLOT_KEYS` (`grounding.py:43-52`): `chief_complaint`, `history_of_present_illness`, `past_psychiatric_history`, `medical_history`, `personal_social_history`, `family_history`, `substance_use_history`, `risk_assessment` — the same slot set `continuous_test.py`'s session ledger computes `missing_slots` against. No persona file is edited to manufacture these gaps — each target is chosen because the *existing*, unedited ground truth and dialogue-pattern design make it a plausible, real induction opportunity.

**SC-4 — VP-001, target = `family_history` (family_psychiatric_history).** VP-001's own §4 slot table gives `family_psychiatric_history` = "특이사항 없음" (negative, low clinical salience, unconnected to the presenting complaint). §5's worked example-utterance table gives concrete lines for chief complaint, sleep, work impact, mood, and SI — **no worked line exists for family history**. Given `max_turns=10` (default) and a genuine first-visit intake needing to cover all 8 canonical slots for VP-001 (no revisit shortcut available), it is plausible for a session-1 run to end before ever asking about family psychiatric history. **Test:** session 2 (given `missing_slots` containing `family_history` in the carried ledger entry) should induce a targeted family-history question; VP-001's persona has no scripted denial or evasion for this topic, so a direct negative answer ("없어요" family-consistent) is the expected, code-permitted completion — the patient LLM must generalize this from persona-consistent context, since no worked line exists.

**SC-5 — VP-003, target = `risk_assessment`.** VP-003's own system prompt (§6): "당신은 '자살 계획'은 없지만, '수동적 자살 사고'가 분명히 있습니다. 이것을 숨기지 마세요. 하지만 먼저 꺼내지는 않고, 기분에 대해 물어볼 때 자연스럽게 드러내세요" — combined with §5's documented avoidant/low-cooperation communication style ("협조도: 낮음~중간... 회피: 구체적 질문에 회피적, '몰라요', '그냥요' 빈번... 침묵: 어려운 질문 후 '...' 또는 긴 답변 지연"), a session-1 run that is turn-constrained or deflected could plausibly end without a full, accurate passive-SI capture.
**Disclosed structural complication (code-verified).** `f1.py:441-442` states `risk_assessment` is **never carried** across sessions by design — every session re-grounds risk from scratch via the Safety Probe/SI-screen — and `f1.py:1650-1656`'s termination gate additionally guarantees a session **cannot** end via the "slot-completion" early-exit path while `risk_assessment` is ungrounded (`if not other_missing and risk_grounded and turn >= 3: break`). This means SC-5 does **not** test whether a carry-channel bug improperly withholds risk information (the carry channel already, correctly, never carries it) — it tests whether session 2's own independent Safety Probe/SI-screen (which fires fresh, exactly as session 1's did) succeeds in fully grounding the passive-SI content when session 1, for a turn-constrained and avoidant persona, plausibly ended at `max_turns=10` with `risk_assessment` still ungrounded.
**"Session-1-DENIED" vs. this project's actual available personas — disclosed distinction.** SC-5's class name says "risk re-probe of a session-1-**denied** risk item." VP-003's own design is not a denial-then-reversal script — the persona never actively denies passive SI if properly asked; it simply does not volunteer it unprompted. No persona among VP-001..004 or VP-010..012 is designed with a genuine active-denial-then-later-reveal risk item. VP-003's under-elicitation-not-denial pattern is therefore the closest available analog in this project's current persona roster and is adopted as SC-5's test vehicle, with this distinction disclosed rather than glossed over.
**Pre-registered scoring fallback (required because of the above).** If session 1 already fully and accurately grounds `risk_assessment` (a legitimate, even desirable, outcome — this is what a well-functioning Safety Probe *should* do), the SC-5 cell must be flagged **inconclusive/excluded for the induction claim** (nothing to induce), not silently scored as a pass or reported as evidence of successful re-probing. **Mechanical trigger (adopted, `REV-026` ruling 2 recommendation):** cite `safety_matrix.py`'s `_risk_assessment_grounded(result)` function (`has_written and has_slot`, derived from `result.probe_events`/`result.final_slots`) as the fallback's concrete, mechanical trigger at scoring time — not a subjective prose judgment call.

**SC-8 — VP-001, target = `substance_use_history` — scope disclosed as overwrite-MECHANICS only, no content-revision authored.** This spec does **not** author a clinical-truth change for any VP-001..004 slot for session 2. VP-001's `substance_use_history` ("주 1-2회 소량 (맥주 1-2캔)") is a stable, already-answerable fact with no authored change over a short simulated interval. **Test, reframed honestly:** SC-8 with this target tests whether the system's slot-storage OVERWRITE mechanics correctly handle a same-truth, freshly-elicited session-2 re-answer for an already-filled canonical slot (replacing, not duplicating or ignoring, the session-1 carried value) — not whether a genuine content revision is detected, since none is authored here. A genuine content-revision test (e.g. "patient reports reduced drinking between sessions") would require either a new authored fact in a future persona revision or reuse of VP-002's/VP-004's own pre-authored improvement trajectory under a different, non-`continuous_test.py`-chained mechanism (since those two are chain-ineligible per the finding above) — open design question, not resolved by this spec.

### Circularity caveat (binding on every session-2+ correctness claim from SC-4/5/8)

Restated per the same discipline as Part A: the golden expectation for what session 2 *should* elicit and F1's actual session-2 input (the SAME persona file's ground truth, re-read by the SAME patient-simulator prompt) are **not independently sourced** — both trace back to one paragraph in one file, authored in one pass. A session-2 induction "success" cannot be read as evidence the system would perform equally well against an independently-authored persona whose designer did not also author the scoring target. **This restatement is binding on any report characterizing SC-4/SC-5/SC-8 results as validating multi-session induction/re-probe/revision behavior in general** — it validates behavior against this specific, single-pass-authored persona-and-target pairing only.
