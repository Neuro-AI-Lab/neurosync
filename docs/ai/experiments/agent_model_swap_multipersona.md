## Ⅰ. 정성 평가 — 통제 대화 품질 (3 dialogue 모델 × 6 페르소나)

**설계**: 페르소나별 **고정 환자 4턴 스크립트**(PatientLLM이 표준 문진질문 4개에 답한 발화를 캡처·동결)를
Solar/EXAONE/A.X의 `DialogueAgent`에 **byte-identical**하게 주입. safety·session_state 고정. F1 오케스트레이션
없이 dialogue만 격리. 18런 전부 실행(403 0회, 폴백 오염 없음: model_used 단일 확인).

### 모델별 집계 (6 페르소나 · 30턴)

> ⚠️ **2026-07-25 정정**: 최초 집계는 harness가 `PROMPTS_BASE_DIR` 미설정으로 **폴백 dialogue
> 프롬프트**로 실행된 값이었음(세 모델 공통이라 비교는 공정했으나 production 프롬프트 아님).
> **실제 v2 프롬프트로 재실행한 값이 아래 "실제 프롬프트" 행**. 결론(A.X 최안정)은 유지.

**실제 프롬프트(v2) 재실행 — 확정값:**
| config | 질문율 | 빈 응답 | 원문노출† | 내부 재시도 | **출력 결함 합** |
|---|---|---|---|---|---|
| **ax_dialogue** (A.X) | **24/30** | 0 | 0 | 3 | **0** |
| solar_baseline (Solar) | 22/30 | 0 | **4†** | 5 | **4** |
| exaone_dialogue (EXAONE) | 18/30 | **3** | 0 | 1 | **3** |

† Solar "원문노출" 4건 = 응답이 길어 **512토큰 상한에 잘려 JSON 미완성 → 파싱 실패로 원문 노출**(VP-011 집중, T1은 빈 객체 `{}`). 순수 JSON 누출이 아닌 **장황함+토큰상한 절단** 아티팩트. A.X는 간결해 절단 0.

*(참고) 폴백 프롬프트 최초값: A.X 29/30·결함0 / Solar 28/30·결함0 / EXAONE 22/30·결함2.*

**실제 프롬프트에서의 확정 결론**: **A.X가 여전히 유일하게 결함 0 + 최고 질문율(24/30)**. Solar는 실제 프롬프트에서 응답이 장황해져 토큰상한 절단 4건 발생, EXAONE은 빈 응답 3건. → **A.X 최안정 결론 강화**(오히려 실제 프롬프트에서 Solar 대비 우위 확대).

### 정성 발견
1. **A.X — 6개 페르소나 전부 결함 0, 질문 29/30(최고).** "공감 한 줄 + 질문 한 줄" 구조가 프로파일과 무관하게 일관. 단일 페르소나에서 확인된 우수성이 **다양한 임상군에서 재확인**됨.
2. **Solar — 결함 0이나 내부 재시도 5회(near-dup 가드)** 로 가장 많음. 출력은 깨끗하나 같은 질문 재활용 경향을 가드가 잡아 재생성. 안정적이나 반복 억제 부하.
3. **EXAONE — 빈 응답 2건(VP-001·VP-010 모두 T2 "정신과 과거력" 질문에서)**. 다중 페르소나에서도 출력 불안정 재현. 특히 **VP-010(축소보고형)에서 질문 1/5** 로 붕괴 — 캐물어야 할 프로파일에서 가장 취약. (JSON 원문 누출·비문은 이 배치에선 미재현이나, 앞선 실행들에서 관측된 바 있어 산발적 결함으로 판단.)
   - ※ EXAONE 재시도 0 = 빈/불량 출력을 **가드가 잡지 못하고 그대로 수용** → 자가 교정 없이 조용히 실패. Solar/A.X의 재시도(자가 교정 발생)보다 오히려 위험한 양상.

**대표 붕괴 사례 — EXAONE / VP-010 (축소보고형):**
```
[환자 T2] 네, 지금까지 그런 건 전혀 안 해봤어요. 그냥 점검 차원에서 와봤어요. 큰 문제는 아닐 것 같아서요.
[AI  T2] (빈 응답 — 축소보고 환자에게 재질문해야 할 결정적 지점에서 아무 말도 못 함)
```

## Ⅱ. 정량 평가 — 지연·완주·안정성 (4 config × 4 페르소나, F1~F5 라이브·RAG DB)

**config**: solar_baseline · mix_optimal(추천 배치) · ax_dialogue · exaone_dialogue. **페르소나**: VP-001·003·010·012.

### 정량 발견
1. **완주율: 16/16 전 구성·전 페르소나 F1~F5 완주.** 모델 조합·임상 프로파일과 무관하게 파이프라인 무붕괴.
2. **속도**: ax_dialogue 최속 중앙(5,037ms) ≈ solar_baseline(5,246ms) < mix_optimal(5,934) < exaone_dialogue(6,007).
3. **최악 tail**: solar_baseline 최소(8.0s)로 가장 예측가능. **exaone_dialogue 최악(24.6s @ VP-010)** — EXAONE tail 불안정이 다중 페르소나에서 재확인.
4. **재시도/복구**: solar_baseline 최소(6.0). ax_dialogue·mix_optimal 높음(15~16) = **A.X의 native JSON 미지원 → 프롬프트+repair 오버헤드**(내부적으로 흡수, 비치명). exaone(12.8)은 tail로 발현.

## Ⅲ. 종합 — 정량 × 정성 교차

| 모델(dialogue) | 정성(결함/질문) | 정량(중앙/tail/완주) | 종합 판정 |
|---|---|---|---|
| **A.X** | **결함 0 · Q 29/30** | 최속 5.0s · tail 12.3s · 완주 | **dialogue 유력 후보** (단 JSON-repair 오버헤드) |
| **Solar** | 결함 0 · Q 28/30(재시도 5) | 5.2s · **tail 8.0s 최소** · 완주 | **안전한 기본선** (반복 억제 부하) |
| **EXAONE** | **결함 2 · Q 22/30** | 6.0s · **tail 24.6s 최악** · 완주 | **dialogue 부적합** (빈 응답·tail) |

### 최종 결론
1. **dialogue = A.X 또는 Solar 둘 다 실사용 가능**, **EXAONE는 dialogue 부적합**(정성·정량 양쪽에서 최하).
2. **A.X 확정 평가**: 다중 페르소나 통제에서 **결함 0·질문 최고**, 정량 **최속 중앙+전 완주** → 이전 "문진 미진행" 오판을 완전히 뒤집고 **dialogue 최적 후보**로 확정. 유일한 비용은 native JSON 미지원에 따른 repair 오버헤드(비치명, tail 양호).
3. **Solar**는 tail·재시도 효율이 가장 좋아(예측가능성↑) 여전히 안전한 기본선. 반복 억제(near-dup)만 개선하면 최상.
4. **EXAONE**: 정상 문장력은 최상급이나 **빈 응답(축소보고형에서 치명)·tail 24.6s** → json_object 출력 가드와 서빙 tail 안정화 전엔 생성 에이전트 투입 보류.
5. **추천 배치 재조정**: dialogue를 A.X로 두는 것이 정량·정성 모두 근거 있음. `mix_optimal`(dialogue=A.X)는 유효하나 중앙 지연이 다소 높아(5.9s), **dialogue=A.X + 나머지 Solar 고정**이 속도·품질 균형상 더 우수.

## 한계
- 정량은 4 config × 4 페르소나, 정성은 3 모델 × 6 페르소나 — 각 1회 실행(비결정성). 근소차는 재현 필요, 큰 경향(완주·A.X 우수·EXAONE tail/빈응답)은 반복 관측으로 견고.
- 정성은 dialogue 격리(고정 스크립트) — **위기 감지 정확도·리포트 정합성·grounding**은 safety/handoff 등 타 에이전트 소관으로 본 평가 범위 밖.
- 재시도/복구 카운트는 near-dup 가드·JSON repair·fallback을 합산한 근사치(계층 상이). 세분화는 후속.
